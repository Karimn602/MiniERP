## What changed

**Greaz's official menu is built in.** After enrollment the owner sees
"Greaz's official menu has not been loaded yet" on the Register, reviews the 33
items (27 menu items, 4 add-ons, 2 combo upgrades), chooses the VAT rate and
whether the printed prices include VAT, confirms, and loads it. See
`docs/OFFICIAL-MENU.md` for exactly what is created, what an existing database
keeps, and what the restaurant still has to confirm.

**Register.** New section tabs in printed-menu order (Fries, Appetizers,
Combos, Dessert, Combo upgrades). Dipper Chicken, Chicken Loaded Fries and the
Greaz Box ask for their free sauce or dips when added; the answer prints on
the kitchen ticket. Paid extras are their own priced lines.

**Fixed along the way (found by the independent review):** a barcode answer
that arrives after its order was already posted or cleared is now dropped
instead of being added to the next customer's order. This applied to every
scanned item before 1.2.0.

**No migration.** Installing 1.2.0 over 1.1.x keeps the database exactly as it
is and adds nothing to it until the owner chooses to load the menu. Take the
operator backup first anyway (`docs/OPERATOR-BACKUP-RUNBOOK.md`).

## Verified, and not verified

* Verified: `npm run verify` on the final source (typecheck, 60 files /
  1,227 Vitest tests, 1,129 Rust tests, cargo check) in the development tree.
* Inside the clean build worktree (`verify-in-worktree.txt`, run AFTER the
  installers were built): typecheck and all 1,227 Vitest tests passed; Rust
  passed **1,128 of 1,129**. The one failure,
  `auth_session::the_fatal_startup_dialog_is_wired_to_the_windowless_path_only`,
  is a pre-existing test that searches `lib.rs`'s SOURCE TEXT for a bare LF
  line break, and a
  fresh checkout under `core.autocrlf=true` has CRLF. Proven: with only that
  file converted to LF the test passes in the same worktree. It is not a
  defect in the application and does not affect the installers. The test now
  normalises line endings (test-only follow-up commit, after `19fb4d2`) and
  passes on both LF and CRLF checkouts. Unlike 1.1.1, verify did not run
  before the build in this worktree.
* Verified: 16 Rust tests against real migrated SQLite databases (fresh load,
  every price and section, repeat refused, existing-database safety, store
  scoping, owner-only, sale of seeded items, Coming Soon refused) and component
  tests that render the real Register and dialog (choices reach the posted
  line; nothing posts while a choice is open; a stale scan is dropped).
* Verified: independent Codex review, four rounds, final PASS.
* Verified: the protected Production and Training databases on the build
  machine were byte-identical before and after this work.
* **NOT VERIFIED:** the installed desktop application. No real-WebView2
  walkthrough, no key events into the real window, no restart test of an
  installed build, no Production/Training side-by-side run, no 1366x768 visual
  check of the new tabs. The walkthrough script exists
  (`dev/menu/walkthrough.mjs`, phases `fresh`, `restart`, `exist`) and has
  never been executed.
